A Mac app for code review

Don’t read the diff. Fathom it.

Fathom reads a pull request and tells it back as a short paper: what was wrong, the idea that fixes it, how it works now, and the choices it makes. One sentence and one figure at a time.

01Premise

Agents write the lines. You own the shape.

When an agent writes the code and a bot checks that it does what it says, reading a diff line by line is no longer the reviewer’s job. The job is understanding the move.

What was wrong before? What is the one idea that fixes it? How does the system behave now, and what did the author give up to get there? A diff answers none of these directly: it is ordered by file rather than by thought, and gives every line the same weight.

Fathom reorders the change into the shape you would draw on a whiteboard for a colleague, and draws it. It never tells you whether the code is good; that judgement stays with you.1

1Every figure here is Fathom reading one of the author’s own pull requests, walkai #46, unedited.

02Method

How a reading is made

Fathom fetches the pull request and its diff through your GitHub CLI, labels every hunk, and asks Claude, through your own Claude Code, for two things at once: an outline of the change, and its story. The story is told with read-only access to a shallow checkout of the pull request, so its figures name real types and functions. Both stream onto the page as they are written, and are kept on your Mac.

03Anatomy

Six sections, the same every time

Each section is one sentence and one figure, so you always know where to look. Most of the time the abstract alone tells you what you are looking at.

01

The problem

How things went before, as a sequence diagram, with the step where it hurt marked in red.

02

The idea

The key idea in a sentence, and the few parts that carry it, the new ones in green.

03

How it works now

The same actors after the change, and what travels on every arrow. Flip to Before to compare.

04

Choices it makes

Each decision as a fork: what was chosen, over what, and why, stated or inferred.

05

Promises that change

Interfaces whose shape changes, member by member: endpoints, types, tables, config.

06

Where to look

The two to four places in the code to read if you read nothing else.

04Review

When you want the lines, they make sense

Changes has the whole diff regrouped into chapters by purpose, each marked read, skim or skip, with a short note above every change. What people and review bots have already said on GitHub sits on the lines it is about. Click a line number to comment, reply in a thread, or suggest a change, and send it all as one review, under your own name.

05Appearance

On paper by day, on water by night

Fathom reads as well at noon as at midnight. The light appearance is warm paper and ink rather than white, with the colours that mark what is new, broken and changed deepened to read on paper, and code set in printed inks. The dark one is deep water. It follows your Mac, or you can choose one in Settings.

30s

From a pull request link to its whole story. The headline arrives in five.

0s

To open it again. Readings are kept on your Mac.

0keys

No account or server. It runs on your GitHub CLI and Claude plan.

06Principle

Fathom never tells you whether the code is good. It shows you what the code does.

So there are no verdicts, no risk scores and no robot approvals. A choice the pull request does not state is marked inferred, and every figure links back to the lines it was drawn from.

07Install

Free, open source, yours in a minute

  1. Download Fathom, drag it into Applications and open it. It is signed and notarized by Apple.
  2. Install the GitHub CLI, then press Sign In to GitHub in Fathom. It shows a one-time code and finishes by itself.
    brew install gh
  3. Install Claude Code and sign in once. Readings use your Claude plan.
    curl -fsSL https://claude.ai/install.sh | bash
  4. Pick a repository, then a pull request. Or paste a link.
