Abstract

When an agent writes the code and a bot checks that it does what it says, reading a diff line by line is no longer the reviewer’s job. The job is understanding the move. Fathom reads a GitHub pull request with Claude and tells it back as a short paper: the problem it solves, the idea that solves it, how things work now, the choices it makes and the promises it changes, with the code a click away. It runs on your own GitHub CLI and Claude Code; there is no account, server or key.

Keywords: code review, pull requests, coding agents, comprehension.

I

The Premise

What is left for a reviewer when the lines write themselves.

Agents now write much of the code in a pull request, and checks and review bots confirm that it does what it claims. What is left for the human reviewer is the part no bot can do: to understand the change well enough to own it. What was wrong before? What is the one idea that fixes it? How does the system behave now, and what did the author give up to get there?

A diff answers none of these directly. It is ordered by file rather than by thought, and it gives every line the same weight. Fathom reorders the change into the shape you would draw on a whiteboard for a colleague, and draws it, as sequence diagrams and small figures of the parts that carry the idea.

It never tells you whether the code is good. That judgement stays with you; Fathom only makes sure you have what you need to make it.

II

The Method

Two readings at once, both streamed onto the page as they are written.

Fathom fetches the pull request and its diff through your GitHub CLI and labels every hunk of the diff. It then asks Claude, through your own Claude Code, for two things at once: an outline of the change, and its story.

The story is told with read-only access to a shallow checkout of the pull request’s head, so its figures name real types and functions rather than guesses. Both readings stream onto the page as they are written, and are kept on your Mac, per commit, so a pull request you have read before opens at once.

III

Anatomy of a Reading

Six sections, the same every time, so you always know where to look.

1

The problem

How things went before, as a sequence diagram with time running down the page, and the step where it hurt marked in red.

2

The idea

The key idea in a sentence, and the few parts that carry it, the new ones in green. Point at a part to see only what it touches.

3

How it works now

The same actors after the change, with what travels on every arrow. Flip to Before to compare.

4

Choices it makes

Each decision as the fork it was: what was chosen, what it was chosen over, and why, marked stated or inferred.

5

Promises that change

The interfaces whose shape changes, member by member: endpoints, types, tables, configuration.

6

Where to look

The two to four places in the code to read if you read nothing else, each a click from the diff.

Plate III

IV

The Review

When you want the lines, they are in an order that makes sense.

Changes has the whole diff regrouped into chapters by purpose, each marked read, skim or skip, with a short note above every change. What people and review bots have already said on GitHub sits on the lines it is about.

Click a line number to comment, reply inside a thread, or suggest a change, then send it all as one review, under your own name. Fathom never posts anything you have not sent.

A principle

Fathom never tells you whether the code is good. It shows you what the code does.

So there are no verdicts, no risk scores and no robot approvals. A choice the pull request does not state is marked inferred, and every figure links back to the lines it was drawn from.

V

Availability

Free and open source. Yours in a minute.

  1. Download Fathom, drag it into Applications and open it. It is signed and notarized by Apple.
  2. Install the GitHub CLI [1], then press Sign In to GitHub in Fathom; it shows a one-time code and finishes by itself.
    brew install gh
  3. Install Claude Code [2] and sign in once. Readings use your Claude plan.
    curl -fsSL https://claude.ai/install.sh | bash
  4. Pick a repository, then a pull request. Or paste a link.
