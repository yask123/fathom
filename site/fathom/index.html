Abstract

When an agent writes the code and a bot checks that it does what it says, reading a diff line by line is no longer the reviewer’s job. The job is understanding the move. Fathom reads a GitHub pull request with Claude and tells it back as a short paper: the problem it solves, the idea that solves it, how things work now, the choices it makes and the promises it changes, one sentence and one figure at a time, with the code a click away. It runs on your own GitHub CLI and Claude Code; there is no account, server or key.

Keywords: code review, pull requests, coding agents, comprehension, sequence diagrams.

1Introduction

Agents now write much of the code in a pull request, and checks and review bots confirm that it does what it claims. What is left for the human reviewer is the part no bot can do: to understand the change well enough to own it. What was wrong before? What is the one idea that fixes it? How does the system behave now, and what did the author give up to get there?11Every figure on this page is Fathom reading one of the author’s own pull requests, walkai #46, unedited.

A diff answers none of these directly. It is ordered by file, not by thought, and it gives every line the same weight. Fathom reorders the change into the shape you would draw on a whiteboard for a colleague, and draws it. It never tells you whether the code is good; that judgement stays with you.

2How a reading is made

Fathom fetches the pull request and its diff through your GitHub CLI, labels every hunk, and asks Claude, through your Claude Code, for two things at once: an outline of the change, and its story. The story is told with read-only access to a shallow checkout of the pull request’s head, so the figures name real types and functions. Both stream in as they are written, and the reading is kept on your Mac.22Opus by default; Sonnet if you prefer speed. A pull request you have read before opens in no time at all, from disk.

3The sections of a reading

A reading has the same sections every time, so you always know where to look. Each is one sentence and one figure; most of the time the abstract alone tells you what you are looking at.

1The problem
How things went before, as a sequence diagram with time running down the page, and the step where it hurt marked in red.
2The idea
The key idea in a sentence, and the few parts that carry it, the new ones in green. Point at a part to see only what it touches.
3How it works now
The same actors after the change, with what travels on every arrow. Flip to Before to compare.
4Choices it makes
Each design decision as the fork it was: what was chosen, what it was chosen over, and why, marked as stated by the author or inferred.
5Promises that change
The interfaces whose shape changes, member by member: endpoints, types, tables, configuration.
6Where to look
The two to four places in the code to read if you read nothing else.

4Reviewing

When you want the lines, Changes has the whole diff regrouped into chapters by purpose, each marked read, skim or skip, with a short note on every change. What people and review bots have already said on GitHub sits on the lines it is about. Click a line number to comment, reply in a thread, or suggest a change, and send it all as one review, under your own name.

5What Fathom will not do

Principle.Fathom never tells you whether the code is good. It shows you what the code does.

Remark.So there are no verdicts, no risk scores and no robot approvals. Choices it cannot find stated in the pull request are marked inferred, and every figure links back to the lines it was drawn from.

6Installation

  1. Download Fathom, drag it into Applications and open it. It is signed and notarized by Apple.
  2. Install the GitHub CLI [1], then press Sign In to GitHub in Fathom; it shows a one-time code and finishes by itself.
    brew install gh
  3. Install Claude Code [2] and sign in once. Readings use your Claude plan.
    curl -fsSL https://claude.ai/install.sh | bash
  4. Pick a repository, then a pull request. Or paste a link.
